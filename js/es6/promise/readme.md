# 代码执行耗时吗？
 - 程序中存在一些耗时的任务，比如网络请求，定时器等。这些任务我们称作异步任务。

# 异步
 - js 默认是单线程执行的，意味着同一时间只能执行一个任务。

 - 耗时任务会阻塞后续代码的执行，这样会降低程序的执行效率。所以js 设计了一个事件循环机制，来处理异步任务。

# 处理异步任务
 - js 会将同步任务先执行完，然后才会执行异步任务。而在某种场景下，我们是希望等某个异步任务完成后，再执行后续代码。

 1. 回调函数：
    将后面要执行的函数作为参数，传给前面的异步函数，这就会导致前面的异步函数执行完成后，才会调用后面要执行的函数。

    缺点：当异步任务嵌套过多时，会导致回调地狱（排查问题困难，代码可读性差，代码维护困难）。

# Promise

## 是什么
 - Promise 是一个对象，用于处理异步操作的结果。

## 三种状态
| 状态 | 含义 |
| pending | 进行中（初始状态） |
| fulfilled | 成功，携带结果值 value |
| rejected | 失败，携带失败原因 reason |

 - 状态只能从 pending 变为 fulfilled 或 rejected，且只能变一次，不可逆。
 - resolve / reject 是用于改变状态的函数，分别对应 fulfilled 和 rejected 状态。

## 链式调用与状态继承
 - then 一定返回一个新的 Promise（记作 promise2），这就是能 .then().then() 的原因。
 - 下一个 then 拿到什么状态，取决于上一个 then 回调的返回值：
    - 返回普通值：promise2 直接 fulfilled，值就是这个返回值；
    - 抛出异常：promise2 变 rejected，原因是这个异常；
    - 返回一个 Promise（或 thenable）：promise2 会等待它，把它的状态和值"转发"过来。

## 和回调函数相比
 - 回调：把后续逻辑塞进前一个异步函数内部，层层嵌套，形成回调地狱。
 - Promise：先拿到占位对象，在它身上继续注册后续逻辑，形成扁平的链式结构，错误也能统一处理。
